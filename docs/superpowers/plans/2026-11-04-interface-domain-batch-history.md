# 接口领域归属与批次历史统计 Implementation Plan

> **For agentic workers:** Root implements the calculator/report boundary; the historical snapshot agent owns persistence, import hooks, schema and shared fixtures. Never run Maven concurrently in this worktree. Preserve original files with SHA guards.

**Goal:** 报表交易数量及认可差异按接口DETAIL交易码和领域归属；日报、周报分别读取各端批次当时的问题状态和数量。

**Architecture:** 按批次问题快照建立全量交易码索引，由接口DETAIL领域下的交易码集合匹配，忽略问题分组/沙箱作交易归属。V88在出现批次关系保存12项统计JSON及时间，元数据表记录同族唯一OPEN批次；导入写合并后的实际状态，人工处理只刷新OPEN，下一同族批次后旧数据保留。报告严格读取批次快照。

**Tech Stack:** Java17、Spring JDBC、MySQL/H2、Jackson、JUnit5、POI。

**Spec:** Obsidian现有并行回放问题清单三件套中的接口领域归属、批次历史统计快照，PR3提交 `0b493c5`，canonical已安全同步。

## Global Constraints

- 用户已确认同批次同交易码只有一个接口领域，多S码明细可以汇总，TOTAL排除，交易码trim且保留前导零。
- 交易级无需处理扣减、三类交易差异数量及字段级认可资格均以接口交易码匹配完整批次问题，不使用问题group/sandbox决定交易归属。
- 问题总数、类型和未解决分类继续使用批次快照问题分组；不扩展本次业务范围。
- 同族新批次导入冻结其他OPEN；当前人工编辑/审核只更新OPEN。显式同批次重导可重开并覆盖，不能改其他批次快照。RPT/DZ独立，支持零行/daily-only。
- 快照12项键齐全，nullable可显式null；缺meta、缺成员快照、坏JSON、缺必需键均明确报“批次历史统计不完整”，不用current值假冒历史或静默丢未知字段。
- 已有日报/周报文件仍可下载；生成/重新生成缺历史时保留HTTP500并返回明确批次原因。
- 四参计算器委托空接口时不再从问题领域补交易量；生产走六参，两端各自接口与快照，不混批次。

## Review Focus

- 问题页签领域与接口实际领域不一致、问题sandbox错位时，交易归属仍正确。
- 同码多S码/重复问题ID只扣一次；无接口匹配不扣不补；违规多领域不可重复计算。
- 跨批次覆盖数量、交易码、审核或日期，以及旧无需处理晚到审批，不得改变冻结批次。
- 同批次重导、0行、日报only、回滚和RPT/DZ隔离；同族至多一OPEN。
- 缺/损坏历史不能把剩余字段误判“全部解决”，已有缓存无需读取缺失历史。
