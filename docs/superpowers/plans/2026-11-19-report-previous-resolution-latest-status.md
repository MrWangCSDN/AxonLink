# 上一批次问题解决进展修复实施计划

**目标：** 日报和周报保留历史问题范围、总数及类型分类，按生成时最新状态重算上一批次未解决数量、分类与解决率；修正上半区表头为“已分析问题分类统计”。

**唯一设计：** `/Users/java/obsidian/01 Engineering/axon-link-server/回放报表上一批次解决进展-系统设计.md`。

## 接口与约束

- `ReplayReportCalculationDataLoader.SideData.resolutionIssues()` 使用已有 `findLegacyReportIssueStatistics(batch)` 读取该批次成员的当前结论；原 `historicalIssues()`、`metricIssues()` 保留原用途，不解析当前脏影响笔数。
- 计算器增加十参 `calculate`：在原九参入口的 `context` 前加入 `previousResolutionIssues`。原入口保留历史行为；新入口只在历史有效问题 ID 范围内按最新有效状态及重新出现标记分类，分母和所属领域仍取历史。当前无需处理仍在历史分母，历史已排除的问题和其他批次新问题不得进入。
- 当前结论缺失、空白或不能识别时保留历史状态；不改冻结快照，不新增接口、迁移或配置。
- 已生成文件继续直接下载；显式重新生成同时更新 Excel、汇总 JSON 和既有邮件状态。

## 审查重点

- 不能将历史总数和分类整体替换为当前数据，也不能把当前无需处理从历史分母移除。
- 同一问题按稳定 ID 关联；所属领域/沙箱使用历史归属，新增成员不能混入。
- 交易影响笔数和通过率仍沿用既有新旧算法，旧统计未知不得变成已解决。
- 全局合计按问题数量加权，不按领域百分比取平均。
- 已生成报表需要部署新代码后显式重新生成，不能声称现有远端报表已自动修复。
