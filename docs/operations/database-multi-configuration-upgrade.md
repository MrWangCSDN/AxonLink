# 同表多配置升级与联调

本次同时涉及 Axon 服务、Axon 前端、BD service、BD Spark 和 BD 元库，须配套升级。工程设计的唯一现行版本位于 Obsidian 的 Axon/BD 三件套；本文只记录部署与验证步骤。

## 升级顺序

1. 在既有 Axon 数据库版本基础上执行 `src/main/resources/db/daoindex/V99__replay_db_compare_configuration_identity.sql` 一次。该脚本给登记和冻结版本增加配置名称，回填普通登记的真实来源，并建立持久编号表。保留旧行空名称标记，勿批量改写历史固定代码。
2. BD 无等待或运行任务时，按实际元库方言执行增量脚本一次：PG 使用 BD 仓库 `sql/add_bcomp_configuration_identity_new.sql`，GDB/MySQL 使用 `sql/add_bcomp_configuration_identity_gdb.sql`。后者 DDL 会隐式提交，重试前核对已完成列与表。
3. 配套更新 BD service、Spark 和前端，再更新 Axon 服务及前端。空库安装使用更新后的完整 DDL；已有库使用增量脚本，不能重复创建永久映射表。
4. 在 Axon 以“新增同表配置”登记条件，生成并下载 NEW 脚本，经 BD 的 Axon 脚本导入接口导入。不要在元库直接执行生成脚本：BD 导入器负责把包内序号转换成永久内部编号，并在事务中保护旧任务、参数和结果。
5. 导入有历史身份歧义时先核对已有配置及结果对应关系，处理明确错误后重试；不能清空永久映射来绕过校验。

## 身份与兼容

- 首个配置优先用真实表名 `a`，后续使用 `a_1`、`a_2` 等。碰撞允许跳号，删除后编号不复用，编辑或重新登记不换代码。
- SQL 仍查询真实表 `a`。BD 固定 `BCOMP_NAME` 与内部 `BCOMP_INDEX` 永久绑定；Axon 脚本内的 index 仅为本包三表关联号。
- 问题 ID 保留旧格式：`a`、`a-amount`；兄弟为 `a_1`、`a_1-amount`。字段总数、一致字段和跨批遗留按固定配置分别统计。
- NEW17 在原14列后增加 `source_table_name,configuration_name,configuration_scope`。旧格式保留兼容；新的额外配置不能使用缺少身份信息的 LEGACY 脚本。
- 不得截断 Axon 的配置序号表或 BD 的 `TSS_BCOMP_CONFIG_ID_NEW`、`TSS_BCOMP_CONFIG_ALLOC_NEW`。旧审计、版本、问题及表状态中的代码也可能仍有占用意义。
- 字段登记 Excel 仅面向物理表的普通默认配置；别名冲突或自定义 SQL 投影请在登记页面选择配置处理。

## Excel 回导及报表核对

1. BD 来源连接显示名设为 `528`，目标连接显示名设为 `ccbs`，使正常导出的环境数量表头符合 Axon 现有契约。显示名在执行发布时冻结，修改当前连接不会重写旧结果。
2. BD 正常执行并导出 Excel，旧“表”列保留固定配置代码，末尾增加真实表、配置名称与条件展示列。
3. Axon 回导时选择对应冻结登记版本和批次。额外配置的真实来源来自该版本，不能通过去掉数字后缀推断。
4. 核对两配置独立的问题 ID、领域及字段数。例如每配置选 `id,amount`，总字段为4；两个 `amount` 均有差异，则不一致字段2、一致字段2。
5. 报表“上一批”取最近更早业务日期中最后导入的一批。遗留只计两批都实际出现且当前缺陷修复日期为空的问题；前批问题在本批未出现时不计。
6. 单独回导某条同源配置时，缺席兄弟的问题、历史与最近表状态应保持。

本地验证不能替代现场 GaussDB 方言和实际 Spark 集群部署验收。
