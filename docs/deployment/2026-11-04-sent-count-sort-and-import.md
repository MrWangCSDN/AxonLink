## 排序

在回放问题清单点击“发送交易量”表头排序按钮，依次切换升序、降序、恢复默认。排序针对筛选后的全量数据，之后才分页；空值在两个方向均排最后，0 和大整数按数据库数值比较。相同数量沿用原业务顺序。

“发送交易量”“出现笔数”“全局流水号”三种排序互斥。筛选、翻页、更改每页数量和清单 Excel 导出均保留当前排序；重置条件或切换查询/动账类型会清除排序。

GET 列表、POST 列表 JSON 顶层和清单导出支持 `sentTransactionCountOrder=ASC|DESC`。缺省、null、空白表示默认，非空非法值返回 400；同时传入多个排序时，发送量优先，其次全局流水号、出现笔数。

## 清单 Excel 导出

用户已澄清需求为导出的 Excel 包含发送交易量。清单导出的“发送交易量”位于“出现笔数”前，读取数据库当前值，0 输出为 0，NULL 为空，完整十进制文本保留大整数精度。导出覆盖全部匹配记录，顺序与所选发送交易量排序一致。

导入继续只从本次“接口比对明细”按交易码汇总 DETAIL 发送量，排除合计，按实际 RPT/DZ 批次族覆盖；未匹配或无接口明细时为 NULL。问题页额外的同名列不作为数量来源，也没有新增的问题列数量校验或冲突规则。问题合并、日报替换和数量覆盖仍统一事务。
