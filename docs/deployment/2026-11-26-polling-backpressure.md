# 巡检任务轮询负载修复

## 修改范围

任务列表原来使用固定五秒定时器。请求较慢时会重叠，已启动的定时器在失败后仍继续执行，隐藏菜单也不停止。本次将任务列表、顶部待办计数、系统状态检查改为一轮结束后再安排下一轮。

- 任务列表只在该菜单可见、浏览器页面可见时请求；成功读取到 PENDING/RUNNING 任务后，等待五秒再刷新。
- 系统状态与待办计数保留三十秒基础间隔；浏览器页面隐藏时暂停。
- 请求失败后逐次延长重试间隔，最高六十秒；成功后恢复基础间隔。页面卸载后取消请求和后续调度。
- 切换任务环境、筛选或页码时，旧请求失效，合并刷新到最新条件。
- 后端先取任务页，再按页内任务 ID 聚合明细，按这些任务的环境聚合 SQL 池；空页直接返回。两次读取在同一个短只读事务中复用一条连接和可重复读快照，避免任务重跑替换时混入新旧结果。原有统计条件、筛选、排序及响应字段保留。

本次不调整连接池默认参数和后端自动建图的三十秒轮询，不要求执行数据库迁移。

## 部署与验证

前后端需要一起更新。后端 `src/main/resources/static` 为忽略目录，单独拉取后端源码不会带入新前端资源。采用已有前端打包流程，确认新构建产物进入后端静态资源目录后再发布。

1. 打开巡检任务菜单。在有进行中任务时，通过浏览器 Network 查看 `/api/ai/dao-index/batch-tasks`：一轮结束后约五秒再开始下一轮。
2. 切换其他菜单，确认不再发起任务列表请求；切回后立即读取最新数据。
3. 将浏览器切到后台，确认三处轮询暂停；返回后恢复。浏览器取消请求不保证已在数据库执行的 SQL 会立即停止。
4. 模拟请求缓慢或连续失败，确认没有重叠的请求周期，失败间隔逐步增加。切换筛选时不能显示或打开旧条件的任务。
5. 对比相同环境、状态和页码的任务数量及明细统计，确认结果一致。

后台建图日志中的“轮询失败”仍可能在结果库没有可用连接时出现。本次修复消除了已复现的前端请求放大条件；生产数据库的慢查询、锁等待及连接占用仍需结合现场证据判断。

## 自动验证

前端执行 `npm test` 和生产构建。后端使用 Java 17 执行 `mvn test`；测试运行前需包含真实前端静态资源，鉴权集成测试会访问 `static/index.html`。

DAO 回归测试覆盖页内聚合边界、环境数据库排序规则、原统计条件、分页及空页；轮询回归测试使用真实 Vue 组件和 API 包装，结合可控计时器与延迟响应覆盖慢请求、失败、隐藏、卸载和筛选切换。
