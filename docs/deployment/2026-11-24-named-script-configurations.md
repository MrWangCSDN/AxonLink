# 命名表SQL配置与bd导入

## 升级

1. 在Axon结果库人工执行 `src/main/resources/db/daoindex/V95__replay_named_script_configuration.sql`，新增独立命名配置表；使用新版前后端。
2. bd使用同时支持最大hash分区数和新版Axon导入格式的代码。元库尚无 `TSS_BCOMP_CONF_NEW.BCOMP_MAX_PARTITION_NUM` 时，按元库类型执行bd的 `sql/add_bcomp_max_partition_num_new.sql`（MySQL）或 `sql/add_bcomp_max_partition_num_gdb.sql`，不要重复执行已完成的ALTER。
3. 最大hash分区数默认64，支持1～256的整数（包括100）；它是运行时自动分区数的上限，不是旧的 `BCOMP_PARTITION_NUM`。

## 使用

进入“数据库比对字段登记 → 版本管理 → 脚本管理”，新建并填写配置名称。维护命名方案需要人员登录；操作口令身份不能保存。

导入 `tables.xlsx` 或 `.xls`，支持表头“表名、表中文名、分组、负责人、最大hash分区数”。表名和分组必填；表中文名、负责人可空；分区数列缺失或单元格为空时使用64。最多5000张表，文件上限10MiB。分组使用存款组、贷款组、公共组、结算组、平台组；负责人保存为说明文字，不作为权限账号。

导入先预览，不立即写库；预览会替换当前草稿的表清单。可编辑每表说明、分组、负责人和最大hash分区数，在选中表下维护单表忽略字段。全局忽略字段支持逗号、换行或 `('field_a', 'field_b')` 列表；它只作用于当前这套方案的全部表。

保存时以BASE当前元数据校验全部表及有序主键。全局规则命中某表主键时自动保留；单表设置不能忽略主键。无主键的表不回退到唯一索引，未知表、重复表、无效字段及非法上限均整批报错，不保存部分结果。数值按Excel真实值校验，不依赖显示格式。

保存成功后，该名称进入“SQL配置版本”下拉，选中后直接下载。命名方案独立于历史登记快照，无历史版本也可维护。已有“旧版本（原表）”“新版本（_new表）”仍使用原下载路径；历史筛选、分页不会缩小命名方案的表范围。

每次编辑保存生成新的修订号，同时冻结全字段元数据和脚本。下载不访问BASE，脚本经过GZIP、长度及SHA256校验。其他人已更新方案时，旧修订号保存或下载会返回409，需要刷新后操作。

## bd消费

使用bd的“Axon配置脚本导入”上传新下载的SQL。命名方案输出NEW表格式，在原13个CONF列末尾增加 `bcomp_max_partition_num`；FIELD与TABLE_SQL布局保持。所有主键字段均标记为比对键，忽略字段从字段配置和两侧SELECT中同步移除。

新格式明确给出的上限按脚本值生效；旧8/10/11/13列格式继续保留同编号的既有上限，新编号默认64。导入仍按照完整配置集替换bd的三张NEW配置表，并在同一事务中完成。下载和维护方案本身不会执行这些SQL。

普通字符串和严格UTF8十六进制文本由bd导入器按列白名单解码并绑定，保证中文、单引号和反斜杠文字保持原样；NUL文本拒绝。导入器继续拒绝任意SQL函数、未知列、额外UPDATE及非法数值。

正式设计唯一来源为Obsidian项目目录中的《数据库比对命名脚本配置》三件套及bd《Axon脚本最大分区数导入兼容-系统设计》。
