# 日报统计起点修复

本版只需替换后端和随包前端，继续使用已执行的V88，无新增SQL。

原逻辑只查询本批和上一批，并未递归；但上一批旧历史不完整时，提示补历史会让用户逐批向前处理。本版将该升级边界作为日报统计起点：

- 当前批次快照完整、上一批不存在或缺完整历史时，允许生成本批日报；不要求先生成任何旧日报，也不查询更早批次。
- 汇总信息上区显示“上一批次历史统计未建立（本批次为统计起点）”，不显示上一批零合计。
- 本批下半区及合计的O～U列（上一批未解决数量、解决率和分类）为空；相同汇总JSON保存null，邮件显示也为空。本批J列、分子、分母和成功率照常按真实快照计算。
- 下一批直接使用这批及新批次的原始快照，恢复两批对比，不依赖本批日报文件是否已生成。
- 同族首批可在页面选择生成，标记“统计起点”；已有旧报告需点击“重新生成”应用本版规则。

当前批次自身的历史不完整仍会明确报错；SQL等其他运行异常不会降为起点。周报继续要求选中的两个批次历史完整。不会删除旧历史、清空报告，也不使用当前问题数据回填过去。

验证：后端日报/周报、工作簿、展示JSON/Codec、HTTP与邮件兼容8类155项通过；前端问题清单页面158项通过。实际生成的起始日报已通过旧版Excel汇总提取器回读，未知格为真正空白，未写作零或空字符串数值。
