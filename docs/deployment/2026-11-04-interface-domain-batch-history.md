# 接口领域归属与批次历史统计升级

## 部署

先在回放问题结果库执行 `src/main/resources/db/daoindex/V88__replay_issue_batch_statistics_snapshot.sql` 一次，再部署新版后端。前端资源无需重建。V88 为出现批次关系增加统计 JSON 与记录时间，并新增批次 OPEN/FROZEN 状态表。

## 交易指标来源

以各批次“接口比对明细”的 DETAIL 交易码及所属领域（含沙箱）为准，匹配该批次问题快照；问题清单的分组和沙箱不再决定交易数量归属。交易码仅 trim，保留前导零；同一批次同交易码应只有一个接口领域。多 S 码明细汇总，TOTAL 不重复参与。

交易级无需处理只扣审核通过的影响笔数。字段级认可仍要求存在无需处理且审核通过的问题，并且本批次该交易全部字段级问题的缺陷修复日期非空；任一为空就不补分子。三类交易差异数量也按相同接口归属匹配。问题总数、问题类型及未解决分类仍按问题的责任分组统计。

## 历史快照

正式导入在原事务中保存各出现问题合并后的实际统计值，包括交易码、影响笔数、状态、审核状态、修复日期等12项。当前批次人工编辑及审核刷新 OPEN 快照；导入下一同族批次后，旧批次冻结，后来的审批不会改写旧快照。RPT、DZ 各自独立，零行及仅日报导入同样推进批次状态。捕获快照时锁定对应元数据，确保与冻结操作互斥。

日报分别读取上一及当前批次，周报分别读取起止批次的问题快照和接口明细。报告生成或重新生成均不将历史批次成员连接到当前问题表计算。已有报告文件仍按原缓存下载契约读取。

同批次显式重新导入可重新打开并覆盖该批次快照；它保存本次合并后的结果，不能据此声称恢复了过去当时的审批状态。其他批次快照保持原值。

## 存量数据和不完整统计

升级前的出现记录不会用当前问题值自动回填历史。已有日报/周报仍可下载；旧批次若需重新生成，必须补齐可靠的该批次历史统计数据。缺少批次元数据、成员快照、记录时间，或 JSON 缺键、类型错误、交易码为空、级别不明等情况，生成接口返回 HTTP 500 及明确的“批次历史统计不完整：批次号”提示，不会静默删除未知问题后继续计算。

原导入兼容性保持：旧 Excel 中无法解析的影响笔数以原文保留在快照，导入不会因此新增失败；生成报表时再严格拒绝不可计算的历史，不把未知文字当成 0。审核状态和缺陷修复日期的显式空值继续表示未审核或未闭环。
