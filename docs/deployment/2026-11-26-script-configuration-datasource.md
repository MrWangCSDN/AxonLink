# 命名脚本配置的数据源升级

## 2026-11-27 密码存储变更

用户已确认 CUSTOM 数据库密码改为无需应用密钥的明文持久化。继续使用 V95/V97 和既有 `password_ciphertext TEXT` 列，新建及成功重新保存统一写入 `plain:v1:` 加原始密码，不做 Base64 伪加密，密码前后空格保留。列名为历史兼容名称；数据库该列、导出、备份及副本中的新值可以直接读出密码。页面不回显和日志脱敏仍保留，但不能替代结果库及备份的访问保护。

1. 在 Axon 结果库 MySQL 按顺序执行既有 [V95](../../src/main/resources/db/daoindex/V95__replay_named_script_configuration.sql) 和 [V97](../../src/main/resources/db/daoindex/V97__replay_script_config_datasource.sql)；已经执行的环境无需重跑。本次不增加DDL，不批量回填密码，不重新生成旧冻结脚本或改变原修订。
2. 部署采用新存储策略的后端及配套前端。新建 CUSTOM、提供新密码保存、读取新格式刷新及同目标复用均不需要设置 `REPLAY_DB_SCRIPT_PASSWORD_KEY`；不要为这些操作生成新密钥。即使旧密钥配置无效，也不能阻断新格式。
3. 仅在还需复用旧 `v1:` AES-256-GCM 记录时，可选保留原来的 `REPLAY_DB_SCRIPT_PASSWORD_KEY`。对应 Spring 属性仍为 `replay-database-comparison.script-config-password-key`；旧密钥按需读取，Base64解码后为32字节。同一旧记录由多个实例读取时须使用匹配的原密钥，新生成的其它密钥不能恢复旧密码。
4. 在脚本管理中打开已有的“迁移比对”或新建方案，填写 GaussDB 的主机、端口、数据库、Schema、用户名和密码。刷新已选表后核对字段和主键，再保存并下载。新方案在完全不设置上述密钥的部署中也须完成保存、刷新和后续留空复用。导出SQL仍使用无 Schema 限定的表名，不包含数据库凭据。

## 旧密码兼容和重填

旧AES记录有正确旧密钥时可继续用于连接。缺失、无效或错误的旧密钥、旧密文损坏或存储格式未知时，需读取旧密码的保存、刷新和Excel预览返回HTTP422、`SCRIPT_CONFIG_PASSWORD_REENTRY_REQUIRED`，要求重新填写数据库密码；失败保留原凭据、方案和修订，不自动猜测、清空或覆盖。

用户明确提供新密码后，无需读取旧密文或配置旧密钥；通过连接、字段和CAS校验的成功保存写入新格式。使用正确旧密钥复用旧密码后成功保存，也写入新格式；仅预览、刷新不会改写存储。列表、详情和冻结下载不读取密码，旧密码不可读或源库离线仍可下载已保存修订，原字节和摘要不变。`passwordConfigured` 仅表示存在已存值，不保证旧密码可读。

密码输入框不回显已存密码。同一认证目标下留空会保留原密码；改变主机、端口、数据库或用户名时需要重新填写。仅修改 Schema 可以继续使用原密码。保存后“本次保存”选项固定本次修订；其他人员已更新时，旧修订下载会提示冲突，可明确选择当前修订再下载。

## 回退和验收边界

仅支持AES的旧程序不能读取 `plain:v1:` 新值。回退前须准备升级前凭据数据/数据库备份和匹配的旧密钥，或另行完成受控反向迁移；本次不提供自动反向转换。新格式已经写入后，不能仅替换旧程序包并假定凭据仍可复用。备份与回退数据本身也须按含凭据的数据管理。
