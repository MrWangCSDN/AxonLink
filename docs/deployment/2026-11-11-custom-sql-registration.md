# 自定义 SQL 登记升级与验收

## 升级顺序

1. 在结果库执行一次 `src/main/resources/db/daoindex/V91__replay_db_compare_custom_sql.sql`。该迁移依赖既有登记及版本表，旧记录默认 `TABLE`，不需要补录 SQL。
2. 部署包含新前端静态文件的后端。BASE 母库连接与 `replay-database-comparison.base-schema` 沿用既有配置；元数据校验需要读取基础表和 PostgreSQL/openGauss 目录的权限。
3. 用人员账号进入“回放数据库比对字段登记”，点击工具栏“自定义 SQL”。操作口令身份不能保存登记；样本数和分区数沿用既有配置权限。

本迁移会增加登记和版本快照的类型、来源表、SQL及结果结构字段，以及版本主表的 SQL 数量字段。请勿重复执行 ALTER TABLE 脚本。

## 内网验收

- 先校验单表 SQL，例如 `select id, sum(amount) as total_amt from source_table group by id`。确认返回结果列、来源表和人员清单映射。
- 选择结果字段、调整顺序并设置结果比对键。键字段需要参与比对；全表聚合需要显式返回常量键，如 `'ALL' AS result_key`。
- 对同一来源表保存两条不同 SQL，确认稳定编号不同；修改显示名称或 SQL 后编号不变，审计可查看前后内容。
- 生成登记版本，分别下载 LEGACY 和 NEW 配置脚本。在实际两侧业务 Schema 验证 SQL、结果字段顺序及结果键；普通登记的 SQL 仍按原规则生成。
- 执行比对后，导入数据库问题 Excel 时选择该登记版本，确认按稳定编号关联快照、领域和负责人。软删除当前登记后，历史问题及权限继续通过快照中的来源表解析。
- 无效字段、重复别名、无结果键、JOIN、子查询、输入 LIMIT、BASE Schema 变化都应阻止保存或生成版本，并给出错误原因。

## 边界

首期支持单表查询、计算列和聚合，两侧使用同一条查询。SQL输入上限为65535个UTF-8字节，BASE元数据查询超时5秒。列别名需为兼容导入的英文标识符，大小写不敏感唯一，最多100字符。

BASE解析校验不替代实际两侧执行。结果键归一化后的空值、重复值及组合键JSON超过1000字符由现有BD执行器拒绝。实际生产LEGACY DDL及用户业务SQL需要在内网验收。
